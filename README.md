# Траектория

Личный планировщик, построенный вокруг одного фокуса, а не вокруг списка обязательств.

Приложение отвечает на три вопроса: что действительно требует внимания сегодня, чем
я занимаюсь прямо сейчас и что лежит перед глазами. Всё остальное — направления,
проекты, книги, идеи — доступно, но не давит.

Интерактивный прототип, с которого начался проект, лежит в `docs/reference/app_2.html`
и остаётся визуальным референсом.

## Продуктовые принципы

- **Задача не существует без проекта.** Направление задачи всегда вычисляется через проект.
- **Одна активная задача на всё приложение.** Выбор новой снимает предыдущую — та просто
  остаётся обычной открытой задачей.
- **Направление в фокусе и активная задача не могут расходиться.** При попытке создать
  противоречие сервер возвращает 409, а интерфейс спрашивает, что делать.
- **Закрепление — это стикер, а не статус.** Закрепляется задача, но показывается всегда
  вместе с проектом: `проект → задача → направление`.
- **Никакого «бэклога».** Все незавершённые задачи проекта равноправны; отсутствие
  дедлайна не делает задачу задачей второго сорта.
- **Касания принадлежат направлению**, а не задаче, и считают факт работы, а не часы.
- **Напоминания — внешняя память.** Без проекта, без просрочки, с архивом на семь дней.

## Архитектура

```
Браузер / PWA / Tauri
        │  REST (JSON, Zod-контракты)
        ▼
   NestJS API ──────────────┐
   ├─ модули домена         │  Drizzle ORM
   ├─ планировщик доставки  ├──────────────► PostgreSQL
   └─ Telegram-бот (grammY) │
                            │
        общие application services: бот и HTTP API
        вызывают одни и те же сервисы
```

API, планировщик напоминаний и Telegram-бот пока живут в одном процессе NestJS, но
разделены по модулям: `RemindersModule` (доставка) и `TelegramModule` (бот) не знают
друг о друге напрямую — канал доставки подключается через `NotificationRouter`.
Это позволит вынести worker и бота в отдельные процессы без переписывания логики.

## Требования

- Node.js 20+ (проверялось на 22)
- pnpm 10 (`corepack enable`)
- PostgreSQL 16 — локально или через Docker
- Для десктопной сборки — Rust и системные зависимости Tauri (см. `apps/desktop/src-tauri/README.md`)

## Быстрый старт

```bash
corepack enable
pnpm install
cp .env.example .env            # и, при желании, apps/api/.env

# 1. база
docker compose up -d postgres   # или свой PostgreSQL

# 2. схема и демо-данные
pnpm db:migrate
pnpm db:seed

# 3. приложение
pnpm dev                        # API на :3000, веб на :5173
```

Открыть `http://localhost:5173`. Swagger — `http://localhost:3000/docs`.

`pnpm dev` поднимает API и веб параллельно. Отдельно: `pnpm dev:api`, `pnpm dev:web`.

### Переменные окружения

| Переменная             | Зачем                                                            |
| ---------------------- | ---------------------------------------------------------------- |
| `DATABASE_URL`         | строка подключения к PostgreSQL                                  |
| `PORT`                 | порт API, по умолчанию 3000                                      |
| `WEB_ORIGIN`           | источник для CORS, по умолчанию `http://localhost:5173`          |
| `TELEGRAM_BOT_TOKEN`   | токен бота; пусто — бот не стартует                              |
| `TELEGRAM_MODE`        | `polling` (dev), `webhook` (prod) или `off`                      |
| `TELEGRAM_WEBHOOK_URL` | публичный адрес вебхука для production                           |
| `DEV_USER_ID`          | UUID демонстрационного пользователя                              |
| `DEV_AUTH`             | `true` — все запросы от `DEV_USER_ID`; **только для разработки** |
| `APP_TIMEZONE`         | таймзона по умолчанию                                            |
| `VITE_API_URL`         | адрес API для фронтенда (в dev работает прокси Vite)             |

### Про авторизацию

Настоящей авторизации пока нет. В development guard подставляет `DEV_USER_ID`, но
архитектура многопользовательская: `userId` приходит из запроса, а не зашит в сервисы,
и все таблицы им размечены. В production `DEV_AUTH=true` приводит к падению при старте —
приложение не запустится молча с открытым доступом. Заголовок `x-user-id` позволяет
работать от имени другого пользователя (используется в тестах).

## База данных и миграции

Схема описана в `apps/api/src/db/schema.ts`, миграции генерирует drizzle-kit:

- `0000_big_preak.sql` — базовая схема: пользователи, настройки, фокус, направления,
  проекты, задачи, чек-листы, касания, напоминания, доставки, входящие, меню, книги
  и фильмы, привязка Telegram;
- `0001_clever_sumo.sql` — календари и их события.

`pnpm db:seed` идемпотентен: повторный запуск ничего не дублирует (отметка в
`seed_markers`). Загружаются пять направлений, тринадцать проектов, тридцать одна
задача, около двухсот касаний за полгода, напоминания на сегодня, книги и фильмы,
меню и входящие.

## Напоминания

Планировщик (`@nestjs/schedule`) раз в 30 секунд ищет наступившие напоминания.
Redis не нужен:

1. считается момент доставки в таймзоне **пользователя**, а не браузера;
2. создаётся `reminder_delivery` с уникальным `idempotency_key`
   (`alert:<id>:<дата>:<время>` или `digest:<userId>:<дата>`);
3. вставка идёт через `ON CONFLICT DO NOTHING`, затем условный `UPDATE ... WHERE
status = 'pending'` — так доставку забирает ровно один исполнитель;
4. неудача повторяется до трёх раз, затем доставка помечается `failed` с текстом ошибки.

Напоминания без точного времени собираются в одну дневную сводку на время из настроек.

Если `TELEGRAM_BOT_TOKEN` не задан, работает **mock-канал**: сообщение пишется в лог с
пометкой `[MOCK-ДОСТАВКА]`, доставка считается обработанной.

## Telegram-бот

```bash
TELEGRAM_BOT_TOKEN=... TELEGRAM_MODE=polling pnpm dev:api
```

Бот использует те же сервисы, что и HTTP API. Разбор фраз детерминированный
(`packages/shared/src/relative-date.ts`), внешний ИИ не подключается:

| Сообщение                                 | Ответ                                   |
| ----------------------------------------- | --------------------------------------- |
| `Напомни завтра поставить стирку`         | «Напомню 27 августа в утренней сводке»  |
| `Напомни завтра в 12 поставить стирку`    | «Напомню 27 августа в 12:00»            |
| `Напомни в субботу забрать посылку`       | «Ты имеешь в виду субботу, 29 августа?» |
| `Через две недели напомни спросить Джона` | «Напомню 9 сентября»                    |
| `Напомни про доставку`                    | «Когда напомнить?» + кнопки             |
| любое другое сообщение                    | «Сохранил во входящие»                  |

Кнопки под напоминанием: готово, через час, вечером, завтра, удалить. `/cancel`
отменяет последнее созданное напоминание. В development первый написавший боту
связывается с seed-пользователем; в production нужна нормальная привязка аккаунта.

Для production: `TELEGRAM_MODE=webhook` и `TELEGRAM_WEBHOOK_URL`, апдейты принимает
`POST /api/telegram/webhook`.

## PWA

Сборка `pnpm --filter @planner/web build` генерирует манифест и service worker.
Кешируется только оболочка приложения; запросы к `/api` идут по стратегии `NetworkOnly` —
показывать вчерашний дедлайн как сегодняшний опаснее, чем показать ошибку сети.
Для офлайна есть `public/offline.html`.

**Установка в Chrome или Edge:** откройте приложение по HTTPS (или на `localhost`),
нажмите значок установки в адресной строке либо меню ⋮ → «Установить приложение».
После установки оно откроется отдельным окном без вкладок браузера.

## Десктоп (Tauri 2)

Конфигурация в `apps/desktop/src-tauri`. Отдельного интерфейса нет: в dev открывается
`http://localhost:5173`, в production упаковывается `apps/web/dist`. Выданы только
базовые права окна — доступа к файловой системе и оболочке нет.

**Не проверено:** в окружении, где собирался проект, отсутствовали Rust и системные
библиотеки Tauri, поэтому реальная сборка десктопа не запускалась. Конфигурация
написана по документации Tauri 2 и требует проверки на машине с установленным Rust.

## Тесты

```bash
pnpm test
```

- `packages/shared` — 22 теста: разбор относительных дат («завтра», «в субботу»,
  «через две недели», «3 сентября»), арифметика дат и таймзон, recurrence, склонения.
- `apps/api` — 28 тестов на реальной PostgreSQL: полный вертикальный срез
  (направление → проект → задача → активная → закрепление → выполнение), конфликт
  фокуса, фильтры задач, касания, напоминания, архив за семь дней, входящие,
  книги, единый формат ошибок; отдельно — доставка напоминаний, защита от повторной
  отправки и дневная сводка.
- `apps/web` — 7 тестов: связка «направление → проект → задача», отсутствие дубля
  активной задачи в закреплённом, состояние «без фокуса», закрепление и открепление.

Тестам API нужна база `planner_test`:

```bash
createdb planner_test   # или TEST_DATABASE_URL=postgres://...
```

## Что осталось моковым

- **Календари.** Таблицы и события есть, интерфейс показывает их в блоке «Сегодня»,
  но синхронизации с Google Calendar и Яндекс Календарём нет — нужен OAuth и бэкенд.
- **ИИ-разбор входящих.** Работает `MockAiProvider` на детерминированных правилах.
  Интерфейс `AiProvider` готов к подключению настоящей модели; дату он не выдумывает
  и при её отсутствии оставляет поле пустым.
- **Авторизация.** Dev-guard вместо настоящего провайдера.
- **Push-уведомления.** Веб-пуши не подключены; доставка идёт в Telegram или в лог.
- **Экспорт данных.** Кнопка обозначена как будущая функция.
